## Appendix C: Human Joint Naming Standard

**Target: Blender → URDF → USD → NVIDIA Isaac Sim**

### General rule

Every human anatomical joint MUST have a globally unique name.

Format:
```
<side>_<body_region>_<segment>_<joint_type>_joint
```

or shortened:
```
<side>_<segment>_<joint_type>_joint
```

Name MUST uniquely identify:
- body side
- anatomical region
- specific bone connection
- joint type
- digit number (for fingers/toes)

❌ Do NOT use ambiguous names:
- `shoulder_joint`
- `elbow_joint`
- `wrist_joint`
- `finger_joint`
- `interphalangeal_joint`

---

### Side convention

Allowed: `left`, `right`, `center`

Examples:
- `left_hip_coxofemoral_joint`
- `right_knee_tibiofemoral_joint`
- `center_atlas_axis_joint`

---

### Anatomical naming rules

#### Spine
Format: `center_spine_<region>_<level>_joint`

Examples:
- `center_spine_cervical_C1_C2_joint`
- `center_spine_thoracic_T1_T2_joint`
- `center_spine_lumbar_L1_L2_joint`

#### Shoulder complex
The shoulder is NOT a single joint.

Use:
- `right_sternoclavicular_joint`
- `right_acromioclavicular_joint`
- `right_glenohumeral_joint`

❌ Avoid: `right_shoulder_joint`

#### Elbow and forearm
Use:
- `right_humeroulnar_joint`
- `right_humeroradial_joint`
- `right_proximal_radioulnar_joint`
- `right_distal_radioulnar_joint`

#### Wrist
Use anatomical names:
- `right_radiocarpal_joint`
- `right_midcarpal_joint`

❌ Avoid: `right_wrist_joint`

#### Hand and fingers

**Finger numbering:**
- digit1 = thumb
- digit2 = index finger
- digit3 = middle finger
- digit4 = ring finger
- digit5 = little finger

**Thumb joints:**
- `right_digit1_carpometacarpal_joint`
- `right_digit1_metacarpophalangeal_joint`
- `right_digit1_interphalangeal_joint`

Alternative readable aliases (both map to same internal identifier):
- `right_thumb_CMC_joint`
- `right_thumb_MCP_joint`
- `right_thumb_IP_joint`

**Fingers 2–5:**
Every finger MUST specify: `digit number` + `joint type`

Example (index finger):
- `right_digit2_MCP_joint`
- `right_digit2_PIP_joint`
- `right_digit2_DIP_joint`

Meaning:
- MCP: metacarpophalangeal joint
- PIP: proximal interphalangeal joint
- DIP: distal interphalangeal joint

#### Hip
Use:
- `right_coxofemoral_joint`
- `right_hip_coxofemoral_joint`

❌ Avoid: `right_leg_joint`

#### Knee
Use:
- `right_tibiofemoral_joint`
- `right_patellofemoral_joint`

❌ Avoid: `right_knee_joint`

#### Ankle and foot
Use:
- `right_talocrural_joint`
- `right_subtalar_joint`
- `right_toe1_metatarsophalangeal_joint`
- `right_toe1_interphalangeal_joint`

**Toe numbering:**
- toe1 = big toe
- toe2 = second toe
- toe3 = third toe
- toe4 = fourth toe
- toe5 = little toe

---

### Joint metadata specification

Every joint object SHOULD contain:

```yaml
joint:
  name: right_digit2_PIP_joint

  parent_link: right_digit2_proximal_phalanx
  child_link:   right_digit2_middle_phalanx

  anatomical:
    side: right
    digit: 2
    region: hand
    type: proximal_interphalangeal

  simulation:
    type: revolute
    axis:
      x: 1
      y: 0
      z: 0
    limits:
      lower: 0
      upper: 110
```

---

### Blender / Isaac Sim requirements

Joint names MUST:
- be unique in the entire model
- be stable after export
- not depend on Blender object numbering
- preserve anatomical meaning after URDF/USD conversion

Preferred: `right_digit2_PIP_joint`
❌ Avoid: `Bone.034`, `joint_034`

---

### Robotics mapping

| Human joint | Robot articulation |
|-------------|-------------------|
| hinge-like | revolute (finger PIP/DIP, elbow, knee) |
| multi-axis | spherical (shoulder, hip) |
| fused | fixed |

Anatomical name is the source of truth. Simulation joint type is a separate property.

## Appendix E: Naming Convention: Blender → Isaac Sim (USD/URDF)

All objects, bones, and materials involved in robot export
(mesh, Empty-joints, armature bones, materials) must comply
with USD identifier rules: `^[a-zA-Z_][a-zA-Z0-9_]*$`

### Allowed
- Latin letters (a-z, A-Z)
- Digits (not in first position)
- Underscore `_`

### Forbidden
- Cyrillic
- Period `.` (including Blender auto-suffixes `.001`, `.002` — rename manually before export)
- Hyphen `-`
- Spaces
- Name starting with a digit

### Naming scheme
- Visual meshes:    `visual_<part_name>`
- Collision meshes:  `collision_<part_name>`
- Joint empties:     `joint_<parent>_<child>`
- Links (groups):    `link_<part_name>`
- Materials:         `mat_<name>`

### Pre-export checklist — mandatory
1. Outliner → verify no `.00N` duplicate suffixes on exported objects.
2. All names — `snake_case`, ASCII-only.
3. Names match on both sides of joint/link connections (manual check,
   as URDF/USD do not validate this semantically — mismatch causes
   broken kinematics without export error).
