## 2. Границы и допущения

**Объект проверки** — кинематическая модель (7 суставов на руку), геометрия кровати `height = 0.70`, `width = 1.00`, `length = 2.00`, `clearance = 0.10`. Геометрия пациента отсутствует: «пациент» представлен только плоскостью кровати.

**Допущение о строгости 6D (🟡).** Пользователь не уточнил требуемую строгость, поэтому принят вариант «C»: две независимые политики планирования —

- `as_is` — воспроизводит штатный `motion_study.plan_operation` без дополнительных требований;
- `strict_6d` — дополнительно требует по всему переходу `max orientation ≤ 0.5°` и `max |ΔP| ≤ 1.0 мм`; при невыполнении переход помечается `not_found`.

Числа 0.5° и 1.0 мм — **допущение, не подтверждённое пользователем**. При других порогах статусы `strict_6d` изменятся.

**Ориентация P7 (🟢).** Во всех расчётах P7 используется подтверждённый finger при yaw = 80°: `finger = [sin 80°, cos 80°, 0] = [0.985, 0.174, 0]`. Штатная `operation_sequence` задаёт для P7 `PLUS_Y` (yaw = 90°), при котором P7 статически недостижим (0/6, отдельный замер). Это расхождение зафиксировано сознательно.

**P9 (🟡).** P9 отсутствует в `operation_sequence`; цепочка состояний построена отдельно. «Готовая» поза приведена к конвенции P6/P7: `x = x_feed − 0.185`, `y = ±0.25`, `z = height + 0.25`. Выбор готовой позы влияет на результат (см. 8.2) и является допущением.

**Что не проверялось (⬛).** Динамика, моменты, усилия, деформации, реальные ограничения по скорости и ускорению, геометрия пациента и мягких тканей, физический габарит мобильной базы, проходимость 5 см зазора между базой и кроватью.

## 3. Методика и определения метрик

**Ссылочная точка.** Для перехода между состояниями A и B строится линейная интерполяция `P(t) = A + t(B − A)`, `t ∈ [0, 1]`.

- `position_error_mm` — расстояние от ладони до `P(t)` при том же `t`, мм.
- `orientation_error_deg` — угол (rotation vector) между текущей ориентацией ладони и постоянной командной ориентацией операции.
- `endpoint_*` — значения этих величин при `t = 1`.
- `min_margin_deg` — минимальный по суставам запас до ограничения (положительный = внутри пределов).
- `condition` — число обусловленности матрицы Якоби в данной конфигурации (больше = ближе к особенности).
- `valid` — переход, для которого существует допустимая реализация (в пределах, без столкновений) и который удовлетворяет требованиям политики.

**Важная оговорка про `max_position_deviation_mm` (🟢).** В политике `as_is` часть переходов реализуется методом `via_lift` — обходом через точку, поднятую на 0.1 м. Для таких переходов метрика отклонения **по построению** даёт ≈ 100.0 мм (проверено: 100.000015 / 100.000000 / 99.999991 мм). Это высота обхода, а не ошибка слежения. Значения 100.00 мм в таблицах `as_is` нельзя читать как погрешность; в `strict_6d` такие переходы не проходят и заменяются на `task_space` (отклонение 0.00 мм).

**Зазоры.** `arm_bed` — минимальное расстояние руки до плоскости/края кровати. `arm_arm` — минимальное расстояние между руками; метрика **насыщена** неподвижными плечевыми сегментами и даёт почти постоянные 174–184 мм. Информативная величина взаимного сближения — `distal_clearance_m` (предплечье–кисть, радиусы 0.047/0.030). `palm_distance_m` — расстояние между кистями.

**Синхронизация.** Две схемы: `phase` (глобальная нормализация времени, как в `plan_bimanual`) и `stage` (постадийная). `stage_match` = обе руки находятся в одной стадии; доля несовпадений — «рассинхрон стадий».

**Разделение выборок.** 5D и 6D, одноручные и совместные проверки считаются и хранятся раздельно; в таблицах они не смешиваются.

### 4.1. Почему P7 L ломается при c ≥ 0.12

Отказ происходит на первом же переходе `S0_ready → S1_above`: `no_candidate_passed_strict_6d`. Причина — состояние `S1_above` при c = 0.12 имеет статический запас **0.07°** (сустав `sh1`), при c = 0.15 — 0.35° (`el`) и 2.51° (`S1_above`). При таком запасе поза практически сингулярна: обусловленность 43.8 и 50.5, и удержание постоянной ориентации при движении требует скоростей, которые несовместимы с пределами суставов. При c = 0.15 не проходит и политика `as_is`.

Это не эффект выбора метода планирования: состояния статически «достижимы» (6/6), но движение через них в 6D нереализуемо. Именно этот случай показывает, почему одного статического критерия достижимости недостаточно.

### 4.2. Где именно тесно

- **P6 R, c = 0.05, 2.60°** на `w2` в `S3_tension`. Совпадает в статике и в траектории — то есть это не артефакт ветви, а реальное ограничение позы «натяжение» (тяга к себе). С ростом c запас растёт: 7.77° (0.10), 8.39° (0.12).
- **P7 R, c = 0.05, 1.56°** на `w2` в конце перехода `S4_lift → S5_ready`. Эталонное решение той же позы даёт **11.89°**: конечная поза совпадает со стартовой (`S0_ready`), но планировщик приходит в неё на другой ветви IK. Артефакт ветви, устраняемый требованием непрерывности ветви при возврате в готовую позу.
- **P7 L, c = 0.10, 8.88°** в траектории против **1.12°** у эталонного решения `S3_manip`. Обратный случай: эталонная ветвь плохая, траекторная — хорошая.

**Вывод по ветвям (🟢, существенно для интерпретации):** запас состояния — не свойство точки, а свойство пары «точка + ветвь IK». Разброс достигает 18°. Поэтому статические запасы в таблицах — это запас *эталонной ветви*, а не предел возможного; траекторные значения первичны, статические — сопоставимы между c.

### 5.1. Достижение поз отдельно от статуса `valid`

Статус `valid` не используется как доказательство достижения. Проверка выполнена независимыми величинами:

| проверка | результат | где зафиксировано |
|---|---|---|
| endpoint-ошибка ориентации, одноручные, все прогоны | 0.000° (максимум 5.6·10⁻⁵ °) | `endpoint_orientation_error_deg` |
| endpoint-ошибка положения, одноручные, все прогоны | 0.000 мм | `endpoint_position_error_mm` |

| совпадение конечного суставного вектора синхронного прогона с валидированным одноручным | max \|Δq\| = 0.000000°, все 16 сочетаний (2 операции × 2 руки × 2 c × 2 схемы) | сравнение `stage2b1_path_*` и `stage2b1_bilateral_*` |

### 6.1. Как читать этот компромисс

Критерии, по которым сравнивались варианты (пороговые значения — **допущение**, 🟡, заданы не пользователем):

- достижимость 6/6 на обеих руках для P6 и P7;
- запас по траектории, а не по эталонной ветви;
- обусловленность (для следующего этапа — силовых расчётов — высокая обусловленность означает плохую передачу усилия);
- зазоры (до кровати и между руками);
- воспроизводимость при синхронной работе.

Результат:

- **c = 0.20 — исключить.** P7 L статически 2/6, max cond 58.3.
- **c = 0.15 и 0.12 — исключить.** P7 L не планируется в 6D вообще (0/5), при c = 0.15 ломается даже `as_is`. Обусловленность 50.5 и 43.8.
- **c = 0.10 — рабочий, но с оговоркой.** Все переходы проходят, запасы лучше (P6 R 7.77°, P7 R 3.58°), чем при 0.05. Однако у P7 L обусловленность **38.9** уже в статической позе `S1_above` — конфигурация близка к особенности. Для силового этапа это плохо: малые ошибки положения дают большие суставные скорости и усилия.
- **c = 0.05 — рекомендуемый.** Единственный вариант, где обе операции проходят полностью, столкновений нет, а обусловленность остаётся ≤ 12.4 по всем проверенным конфигурациям. Цена: P6 R `S3_tension` — 2.60° на `w2`; P7 R — 1.56° в конце возврата (артефакт ветви, устраняется требованием непрерывности ветви: эталон той же позы даёт 11.89°).

**Итог: c = 0.05 м** — по совокупности запасов, обусловленности и синхронной работы. **Резерв: c = 0.10 м** — если конструктивно необходим зазор больше 5 см или если физический габарит базы не позволяет 5 см.

**Ограничение выбора (🔴).** c — это геометрическое смещение в модели. Реальный габарит мобильной базы, свесы корпуса, кабели и поручни не моделировались. Если платформа физически требует ≥ 0.10 м, принимается резервный вариант, и тогда обязательна отдельная проработка околосингулярной позы P7 L (например, изменение yaw пальца или точки контакта).

### 6.2. Что даёт больше, чем выбор c

Разброс запасов между ветвями IK (до 18°) **больше**, чем разница между c = 0.05 и c = 0.10 (≈2–5°). Практический вывод: выбор ветви и непрерывность ветви вдоль операции влияют на результат сильнее, чем 5 см расстояния базы. Отсюда рекомендация: при планировании фиксировать ветвь преемственностью от стартовой позы и требовать возврата в неё (сейчас это не сделано — см. 4.2).

## 7. P5 — вариант E

Исходная точка P5 (x = 1.315 при c = 0.10) **недостижима в 6D при всех c и на обеих руках** (🟢). Вариант E — подъезд с противоположной стороны: приведение P5 к геометрии P4 (`x = x_near + 0.12`, `y = ±0.25`) в двух ориентациях ладони (`local` — палец +X, `world` — палец −X).

| c, м | исходная P5 L/R | E local L/R | E world L/R | запас E, ° | требуемое удлинение L/R, мм |
|---|---|---|---|---|---|
| 0.05 | нет/нет | нет/нет | нет/нет | — | 390/172 |
| 0.10 | нет/нет | нет/нет | нет/нет | — | 256/221 |
| 0.12 | нет/нет | нет/нет | нет/нет | — | 473/240 |
| 0.15 | нет/нет | нет/нет | нет/нет | — | 315/269 |
| 0.20 | нет/нет | **да**/нет | нет/нет | **0.25** | 566/318 |

Диагностика недостижимости (c = 0.05 и 0.10, все ориентации): цель находится на расстоянии 0.44–0.48 м от плеча, все 24 стартовых решения **не сходятся** (`converged 0/24`), при этом пределы суставов не нарушены и столкновений нет. Остаточные невязки:

| c | ориентация | рука | невязка положения, мм | невязка ориентации, ° | невязка нормали, ° |
|---|---|---|---|---|---|
| 0.05 | local | L | 76.6 | 7.58 | 7.36 |
| 0.05 | local | R | 117.4 | 9.62 | 9.59 |
| 0.05 | world | L | 385.7 | 8.02 | 7.53 |
| 0.05 | world | R | 302.7 | 12.76 | 12.76 |
| 0.10 | local | L | 52.5 | 6.11 | 6.10 |
| 0.10 | local | R | 112.9 | 4.55 | 4.42 |
| 0.10 | world | L | 180.1 | 26.16 | 12.77 |
| 0.10 | world | R | 189.5 | 25.35 | 16.11 |

**Интерпретация.** Недостижимость вызвана не вылетом и не столкновениями, а **несовместимостью требуемой ориентации ладони с положением точки**: на расстоянии ≈0.45 м от плеча рука сложена, и кистевые суставы не обеспечивают заданную ориентацию. То есть вариант E «геометрически близко, но ориентационно невозможно» — это ровно та ловушка, которую требовалось проверить.

Единственное формальное решение — c = 0.20, левая рука, `local`: запас **0.25°** на `w1`, cond 5.16, зазор до кровати 54.9 мм, невязки ~0. Траектория подхода для этой конфигурации посчитана (26 сэмплов, запас 2.30°, зазор 54.9 мм), но запас 0.25° означает практическую непригодность (🔴).

**«Требуемое удлинение»** — параметрическая оценка: расстояние вдоль линии к плечу, на котором задача впервые становится 6D-разрешимой. Это **не** требование к длине звена (немонотонность 256 → 473 мм при 0.10 → 0.12 показывает, что величина зависит от проходимости кистевых конфигураций вдоль линии, а не от простого дефицита вылета). Использовать только как индикатор «насколько далеко» (🟡).

**Вывод по P5:** вариант E в текущей постановке задачу не решает. Нужно либо менять ориентацию ладони на этой точке (не покрыто двумя проверенными вариантами), либо переносить точку контакта, либо признать P5 вне возможностей текущей кинематики.

## 9. Ограничения достоверности

1. **Дискретная проверка (🟢 факт, 🔴 риск).** Столкновения проверяются в сэмплах, а не непрерывно. Максимальный шаг между соседними сэмплами: 14.0° по суставу (P7 R, c = 0.05), до 12.1° (P7 R, c = 0.10), 8.4° в синхронной схеме `stage`; шаг кисти между сэмплами — до 12.7 мм (`as_is`), до 6.3 мм (`strict_6d`). Между сэмплами возможны конфигурации, не проверенные на столкновения. Свип-объём не считался.
2. **Ветви IK (🟢).** Запас зависит от ветви: 1.12° против 19.32° для одной и той же позы (P7 L, c = 0.10, `S3_manip`); 1.56° против 11.89° (P7 R, c = 0.05, `S5_ready`). Статические таблицы — эталонная ветвь. Ни один результат не является глобальным оптимумом по запасу.
3. **Допущение 0.5°/1.0 мм (🟡).** Порог строгой политики выбран без подтверждения. При более мягком пороге часть «не найденных» переходов станет валидной (например, P7 L при c = 0.12: отказ именно из-за строгого порога, статический запас там 0.07–1.65°).
4. **Отсутствие геометрии пациента (⬛).** Проверены только зазоры до кровати, корпуса, базы и между руками. Столкновения с пациентом, нагружение тела, деформации — не проверялись. **Вся операция не может считаться безопасной по результатам этого этапа.**
5. **`via_lift` и метрика отклонения (🟢).** Для обходных траекторий отклонение 100.0 мм — это высота обхода, а не ошибка. Сравнивать `as_is` и `strict_6d` по этой колонке напрямую нельзя.
6. **`arm_arm` насыщен (🟢).** Постоянные 174–184 мм — расстояние между плечами. Для оценки взаимного сближения использован `distal_clearance_m`.
7. **Модель кинематики.** 7 суставов на руку, идеальные шарниры, без люфтов, податливости и погрешностей. Реальные запасы будут меньше.
8. **P9 — построенная, а не заданная цепочка (🟡).** Готовая поза и ориентация пальца выбраны в этом этапе; результат к ним чувствителен.
9. **5D/6D раздельно.** Числа 5D и 6D в отчёте не смешиваются; суммарных «процентов достижимости» нет намеренно.
