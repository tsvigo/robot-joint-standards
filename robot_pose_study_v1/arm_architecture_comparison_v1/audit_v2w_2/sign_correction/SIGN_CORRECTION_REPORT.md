## 1. Что было исправлено

### 1.1 Уравнение движения

Старая форма в `audit_v2w2.py`:

```
tau_act = Tg + M·q̈ + c + Text − tau_spring
```

`Tg` вычислялся как `Σ Jᵀ·m·G`, то есть момент **реально приложенной** силы тяжести,
а `Text` — момент приложенных внешней силы и веса груза. Эти величины — моменты сил,
а не моменты двигателя. Кинетическое уравнение:

```
M·q̈ + c = tau_motor + Tg + Text + tau_spring
⇒  tau_motor = M·q̈ + c − Tg − Text − tau_spring
```

Исправлено: `tau_motor_corrected()` в модуле 1.3.

### 1.2 Гравитационная потенциальная энергия

Было `U = +Σ m·G·p` (знак противоположен физическому гравитационному потенциалу).
Исправлено:

```
Ugravity = −Σ m·G·p         (по всем подвижным точкам)
Ugravity_load = −m_load·G·p_palm
```

Проверка производной: `−dUgravity/dq = Tg` (численно, S2).

### 1.3 Пружина: единая конвенция и пассивность

Элемент задаётся **одним** моментом `tau_spring = k_s·(q−q0)` и энергией
`Uspring = −½·k_s·(q−q0)²`, что даёт `tau_spring = −dU/dq` в обеих физиках.

* **Пассивная торсионная пружина** (`K = −k_s > 0`) ⇔ `k_s < 0`, `U ≥ 0`.
* `k_s > 0` — отрицательная жёсткость: такая характеристика не является пассивной
  пружиной; требуется активный элемент или иная кинематическая передача.
* Цель подбора — `tau_spring ≈ −β·Tg` (`β = 0.9`), то есть против тяжести.
  Старый фит подбирал к `+β·Tg`. Значение `q0` при замене цели не меняется
  (`q0_new = q0_old`), меняется только знак коэффициента: `k_s_new = −k_old`.

### 1.4 Энергетическая проверка

Груз входит и в `M(q)` (масса на ладони в `mass_matrix_audit`), и в `Ugravity`.
Поэтому его вес **не считается вторым внешним источником**:

```
Wmotor = Δ(Kinetic + Ugravity + Uspring)
```

Внешняя работа `Wexternal` в этой модели равна нулю (внешних сил контакта нет).
Для того чтобы это не была «согласованность двух ошибок», груз проверен отдельно:

* `S9`:  `∫ Text·qd dt = −ΔU_load` на переходе S2→S3;
* `S9b`: `dU_load/dq = −Text` численно в каждой из 7 координат
  (`max|dU_load/dq + Text| = 1.4·10⁻⁶` Н·м).

### 1.5 Мощность

Для каждого момента времени: `Pj = tau_motor_j · qdot_j`.

Отдельно считаются: `Σ max(Pj, 0)`, `Σ min(Pj, 0)`, алгебраическая `Σ Pj`,
пик каждого сустава, и интегралы по суставам (`Wpos_joint`, `Wneg_joint`).
Отрицательная мощность **не считается идеально рекуперированной**: она лишь
уменьшает алгебраическую сумму, возврата энергии в модель не добавляется.

### Почему результат изменился с 59.97 на 91.68

Старая формула считала `tau_act = Tg + Mq̈ + c + Text − Ts`. При статике это
давало `Tg − Ts`, то есть она **вычитала** вклад пружины. Однако в правильной
динамике момент пружины стоит со знаком `−Ts`:

```
tau_motor = −Tg − Text − Ts = −75.82 − 15.86 = −91.68
```

То есть пружина с `k_s = −32.14` и `q0 = −22.16°` на рабочем угле `q = −50.43°`
даёт момент `+15.86` Н·м — **в том же направлении, что и тяжесть** (`+75.82`),
а не против неё. Она помогает гравитации, поэтому двигатель должен удерживать
сумму, а не разность. Опубликованные 59.97 Н·м — следствие вычитания
противоположного по знаку вклада.

  не входила; отдельный контроль полного цикла выполнен только для A, 25 кг.

## 9. Остановка итеративных аудитов

Дальнейшие итеративные аудиты архитектур **остановлены** до получения паспортных
данных приводов (момент, ток, напряжение, редуктор, тормоз, КПД). Без них
окончательный выбор архитектуры и подбор приводов невозможны, а уточнение
коэффициентов на неполных данных даёт ложную точность.
