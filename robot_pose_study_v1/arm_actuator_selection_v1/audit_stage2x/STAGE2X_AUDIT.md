## 2. Ошибка исходного критерия отбора

В `selection_calculations.py` отбор шёл по двум независимым условиям:
`T0 >= T_required` и `nMAX >= 17.8 об/мин`. Это **недостаточно**: T0 достижим только
на полке кривой, а `nMAX` — граница кратковременного режима. Правильная проверка —
по точкам (момент, скорость) на самой огибающей: `T <= T_cont(n)` для длительного
режима и `T <= T_peak(n)` для кратковременного [Р].

Например, для `el` тяжёлого режима (476.24 Н·м) отбор дал CanisDrive-50A-160
(T0 = 843 ≥ 476.24, nMAX = 22 ≥ 17.8) — но при 17.8 об/мин у 50A-160 **нет**
непрерывного момента вообще.

## 5. Реакции выходных опор

Проверен исходный алгоритм `/home/v/projects/робот/robot_pose_study_v1/arm_actuator_selection_v1/joint_requirements.py`
(`bearing_loads`): разделение на осевую силу `F·a`, радиальную `|F−(F·a)a|`,
крутящий момент `M·a` и изгибающий `|M−(M·a)a|` **реализовано корректно** [Ф].
Проверен пересчёт на сохранённых позах.

Замечание подтвердилось как **смешение поз**, а не ошибка формул:

| Сустав (L, 100 кг) | В позе максимума sh3: M_приводное | там же: M_изгиб | В своей худшей позе: M_приводное | там же: M_изгиб |
|---|---|---|---|---|
| sh3 | 1068.15 | 59.79 | 1068.15 | 59.79 |
| sh2 | **0.00** | **1068.45** | 1068.15 | 13.32 |
| sh1 | −989.55 | 25.62 | −989.55 | 25.62 |
| el | **0.00** | **475.38** | −475.38 | 15.92 |
| rad | 1.08 | 219.53 | −14.38 | 219.53 |

В опубликованной таблице `bending_overturning_Nm_worst` для `sh2` (1068.45) и `el`
(475.38) взяты **из позы максимума sh3**, где собственный приводной момент этих
суставов равен нулю. Численное совпадение с их приводным моментом в другой позе —
геометрическое совпадение величин весового момента руки относительно начала сустава
при разной ориентации относительно оси [Р]. **Одновременно эти значения не действуют.**

Правило, которого теперь придерживаемся: для каждого из четырёх компонентов указывать
позу и сценарий; не объединять максимумы разных поз в один «расчётный набор».
Полная таблица «худшее по каждому компоненту отдельно» требует прохода по всей сетке
поз (14 040 × 7 суставов × 2 руки) — в этой проверке не выполнялась, осталась UNKNOWN.

## 8. Где это сломается (Pre-Mortem)

1. **Продавливание по скорости.** Если профиль движения возьмут из кинематики
   2Б.2 (до 24.65 об/мин), а привод выберут по T0/nMAX — локоть упрётся в
   `nMAX` 50A/58A. Уже сейчас это видно по §3.4.
2. **Тепловой режим.** Любое длительное удержание с нагрузкой при n > 12.5 об/мин
   для 50A/58A не имеет каталожного S1-обоснования; расчёт на «кратковременный»
   режим без ограничения длительности перегреет привод.
3. **Ресурс Wave Generator.** Работа выше `nN` = 2000 об/мин двигателя/редуктора
   (32B/40B при 17.8 об/мин) снижает расчётный ресурс; TN (178…745 Н·м) меньше
   статических требований тяжёлого режима — ресурс при таких моментах не оценён.
4. **Ремень B1b.** ΔF ≈ 9.5 кН без паспортной прочности — обрыв удержит только
   отдельное устройство, которого в конструкции пока нет.
5. **Масса.** При паспортных узлах обе руки в тяжёлом сценарии ≈ 231 кг; суммарный
   бюджет уже на 20.1 кг выше лимита лифта без семи неопределённых подсистем.
