## 2. Метод и воспроизводимость

1. **Дамп геометрии** (read-only): `blender --background <файл> --python _blender_dump.py`, без вызова сохранения; в JSON попадают все 182 объекта: мировые матрицы, иерархия, свойства (`mass`, `com_*`, `inertia_*`, `phobostype`), габариты bbox, объём меша, материалы.
2. **Тест позы** — только на временной копии `.blend`: поворот `shoulder_joint_empty_2` (ось Z) на 30/60/85° (знак: левая −θ, правая +θ) и комбинированный тест «обе руки вперёд 85°»; пересечения проверяются BVH по реальным мешам (35 collision-оболочек `phobostype=4` исключены). Копия не сохраняется.
3. **Расчёт моментов** — чистый Python (stdlib), по матрицам из дампов: τ⃗ = r⃗ × F⃗, τ_ось = τ⃗·n̂, F⃗ = (0, 0, −m·g·k), r⃗ = G⃗ − O⃗. Для осей X/Y после подстановки: **τ = m·g·k·(−r_y·n_x + r_x·n_y)**.
4. **Повторяемость:** все промежуточные данные сохранены (`arm_dump.json`, `pose_c_results.json`), скрипт детерминирован (без времени/случайности), повторный прогон даёт те же CSV/MD.

## 3. Источники данных: что чем подтверждено

**Факты сцены (Blender, зелёные):**
- иерархия звеньев и суставов, мировые координаты и ориентации фреймов (все фреймы цепочки — identity-ориентация, отклонение ≤ 1.5e-08);
- габариты звеньев (bbox), ладонь 43.9×107.5×107.5 мм;
- свойства `mass`, `com_*`, `inertia_*` у части мешей (числа есть, достоверность — под вопросом, см. §9);
- лимиты/оси суставов в сцене **не закодированы** (нет constraints/драйверов; `drivers_total` в pose-тесте = 0) — они взяты из `robot_joints.md`.

**Факты документации (`robot_joints.md`, жёлтые — не проверяемы сценой):** оси и лимиты семи суставов руки (таблица §4). Соответствие `blender_empty → parent → child` в MD совпадает с иерархией сцены для всех проверенных суставов.

**Допущения анализа (красные, требуют подтверждения):**
- груз 200 кг делится поровну (100+100 кг) — базовый сценарий; несимметрия 60/140 кг — отдельно;
- точки захвата K1–K3t — **тестовые геометрические точки**, не заданные конструкцией;
- удержание статическое, без динамики звеньев и демпфирования; сценарий B — квазистатическая оценка;
- масса звеньев для сценария A не учитывается (нагрузка от груза считается отдельно; собственный вес — §14).

    └─ shoulder_3_link          (пустой фрейм)
       └─ shoulder_joint_empty_2 (сустав j2, ось Z, −90…+90°)
          └─ shoulder_2_link      (пустой фрейм)
             └─ shoulder_joint_empty_1 (сустав j1, ось X, −90…+130°)
                └─ shoulder_link  (плечо, mesh)
                   └─ elbow_joint_empty (локоть, ось Z, −10…+150°)
                      └─ forearm_link   (предплечье, mesh)

                            └─ radioulnar_link (пустой фрейм)
                               └─ wrist_joint_1_empty (ось Z, ±90°)
                                  └─ wrist_pitch_link (пустой фрейм)

Примечание по пальцам: имена звеньев в модели перевёрнуты относительно анатомии — `distal_phalanx` стоит ближе к ладони, `proximal_phalanx` — на кончике (цепочка `mcp → mcp2 → distal → pip → middle → dip → proximal`). Для силового расчёта это не влияет (используются только координаты), но при переименовании под URDF/USD порядок надо исправить.

## 8. Текущая поза — датум анализа

В файле все суставы руки стоят в 0° (максимальный |euler| по цепочке — 0.000000 рад). Руки выпрямлены вдоль ±Y, ладони обращены внутрь, пальцы продолжают ось руки. Матрицы фреймов диагональные (масштаб по осям 0.999…1.259), ориентация — identity; поэтому «наклоны», которые можно увидеть в сырых матрицах, — артефакт масштаба, а не поворот.

**Это не поза подъёма.** В модели не заданы: хват (расстояние между кистями и ориентация ладоней относительно груза), сгибание локтя, наклон/поворот корпуса, положение груза по высоте. Все моменты ниже — для явно указанной позы (покой 0° или «руки вперёд» 30/60/85°), а не для реального цикла подъёма.

## 13. Момент сустава ≠ момент двигателя ≠ прочность

Выше посчитан **внешний момент нагрузки относительно оси сустава** (что должно быть уравновешено приводом в данной позе). Это не то же самое, что:

- **момент двигателя** — момент на валу мотора = момент сустава / (передаточное число × КПД редуктора); без данных о редукторах и компоновке его нельзя назвать;
- **прочность** — напряжения в звене/подшипнике зависят от сечений, материала и распределения усилий; из моментов напрямую не следуют;
- **допустимая нагрузка** — требует запасов, ресурса, жёсткости, точности; в этом аудите никаких запасов не вводилось (все числа — исследовательские, без коэффициентов).

Полный момент на приводе = момент груза + момент собственного веса (§14) + динамика (инерция × угловое ускорение) + трение/потери. Динамика звеньев в этом аудите не моделировалась.

## 15. Оценка массы рук: что можно и что нужно

В файле: сумма масс звеньев руки (по свойствам) — 5.950 кг (L, 12 звеньев) и 7.451 кг (R, 12 звеньев); кисть с пальцами — 0.505 кг (L) и 0.729 кг (R). Но, как показано в §9, эти числа не подтверждены (плотность ≈ 961 кг/м³, массы плеча = массе предплечья).

Пути получения достоверной массы (в порядке надёжности):
1. **CAD/mass properties по реальной геометрии + материалам** — нужны толщины, сечения, заполнение, материалы звеньев; для proxy-боксов результат бессмыслен.
2. **Покомпонентный бюджет** — массы приводов, редукторов, подшипников, валов, кожухов, кабелей, электроники; места установки (в звене / вынесены в корпус) критичны для момента инерции и SW.
3. **Взвешивание прототипа** — самый надёжный, но требует железа.
4. **Оценка по аналогам** — только с явными оговорками и диапазоном.

**Недостающие данные (минимум для инженерного вывода):** массы приводов/редукторов и их расположение; материалы и толщины звеньев; реальная геометрия (не боксы); места крепления груза и тип хвата; кинематика подъёма (траектория, скорости, ускорения); требования по запасам и ресурсу.

Как только массы появятся: τ_привод = τ_груза (таблицы §10–12) + τ_SW (пересчитать с реальными COM) + динамика; далее делить на передаточное число и сравнивать с паспортом мотора.

## 16. Проверка единиц и систем координат

- Blender: `unit_system=METRIC`, `scale_length=1.0` → 1 единица = 1 м; все координаты/габариты в метрах (в отчёте габариты — в мм для читаемости).
- Мировая СК: Z — вверх; **+X — вперёд** (направление взгляда/лифта), **+Y — влево** (левая рука находится при Y > центра корпуса).
- Гравитация: сцена [0.0, 0.0, -9.8100004196167]; в расчёте g = 9.81 м/с², направление −Z.
- Нагрузка — кг (масса); сила — Н; момент — Н·м; плечи — м.
- Проверка масштаба: расстояние j1 → запястье-2 ≈ 800.2 мм, ладонь 43.9×107.5×107.5 мм, размах кистей по K1 ≈ 2171.5 мм. Это согласуется с геометрией модели (плечи разнесены примерно на 0.5 м, каждая рука ~0.8 м, робот — крупнее человеческого масштаба); метрическая система и scale_length=1.0 подтверждают, что единицы — метры.

## 17. Ограничения достоверности

- Все звенья — **proxy-боксы**; плечи сил от центров bbox могут отличаться от реальной геометрии.
- Точки захвата — тестовые (K1–K3t); реальный хват не задан, поэтому моменты кисти — диапазон, а не число.
- Поза подъёма не задана; расчёт сделан для покоя и «рук вперёд», а не для реального цикла.
- Собственный вес — по неподтверждённым массам; COM=0 — вероятный placeholder.
- Динамика, трение, КПД редукторов, кабели, кожухи, прочность — не учитывались.
- Пересечения проверены по bbox/BVH прокси-мешей; зазор 17.6 мм на 85° — оценка, не гарантия.
- Статика всего робота (баланс, опрокидывание, нагрузка на ноги/корпус) — вне рамок аудита.
